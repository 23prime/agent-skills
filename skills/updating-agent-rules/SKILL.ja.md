# エージェントルールの更新

プロジェクトの指示を `CLAUDE.md`（プロジェクトの実質的な正本が `AGENTS.md` である場合はそちら）と `.claude/rules/` 配下のトピック別ファイルのどちらに置くかを判断し、指示が増えていく中で両者を整合させ続けるスキル。対象はプロジェクトスコープのみ：`./CLAUDE.md`（または `./.claude/CLAUDE.md`）、`./AGENTS.md`、`./.claude/rules/`。読み込み順や `paths` frontmatter、サイズ制限などの仕組みについては[公式のメモリドキュメント](https://code.claude.com/docs/en/memory)を参照する。

## ワークフロー

### 1. 現状を確認し、モードを判定する

- `./CLAUDE.md` および `./.claude/CLAUDE.md` が存在すれば読み込む。
- `CLAUDE.md` が別ファイルを実質的な内容としてインポートするだけの薄いポインタになっていないか確認する（例：`@AGENTS.md` を含む）。該当する場合はそのインポート先（`./AGENTS.md`）も読み込む――そちらがプロジェクトの実質的な正本であり、`CLAUDE.md` 自体には手を入れない。
- `./.claude/rules/*.md`（再帰的に）を一覧し、各ファイルの frontmatter と内容を読む。
- 各ファイルの行数を確認する。`CLAUDE.md`（正本が `AGENTS.md` の場合はそちら）が200行を超えている場合は、内容を rules 側に逃がすべきサインとなる。
- **新しい指示を追加する場合** — ステップ2に進む。
- **すでに肥大化した `CLAUDE.md`／`AGENTS.md` を整理し直す場合**（ユーザーからの依頼、または200行超かつ複数の異なるトピックが混在していると分かった場合）— ステップ3に進む。

### 2. 新しい指示の置き場所を決める

新しい指示ごとに、置き場所を以下の観点で判断する。

- **常に関係する、プロジェクト全体の内容**（ビルドコマンド、アーキテクチャ、命名規則など）→ `CLAUDE.md` に追記する。ただしステップ1で `AGENTS.md` が正本だと分かった場合は、代わりに `AGENTS.md` に追記する。
- **特定のファイルやディレクトリにのみ関係する内容**（例：API ハンドラの規約、テストの規約）→ `.claude/rules/<topic>.md` を新規作成または既存ファイルに追記し、対象を絞る `paths` frontmatter を付ける。
- **パスで絞らなくても独立したトピックとして分けるべき内容**（例：全体に関係するが長いセキュリティ要件など）→ `paths` を付けずに `.claude/rules/<topic>.md` を新規作成し、`CLAUDE.md` と同様に無条件で読み込まれるようにする。

### 3. 整理案を提示する

正本ファイル（`CLAUDE.md`、またはステップ1で正本と判明した場合は `AGENTS.md`）の内容をトピックごとにグループ化する。自己完結していて、かつ分量が多い、または特定のファイル種別に限定されるグループについては、`.claude/rules/<topic>.md` への切り出しを提案し、該当ファイルにのみ関係する場合は `paths` frontmatter を付ける。正本ファイルには、すべてのセッションで無条件に見える必要がある短く高レベルなルールだけを残す。

### 4. 矛盾・重複を確認する

最終化する前に、提案内容を既存のすべての `CLAUDE.md`、`AGENTS.md`、`.claude/rules/*.md` と突き合わせる。矛盾や重複するルールがあれば指摘し、どちらを優先するかユーザーに確認する。

### 5. 文言を練り直す

案を提示する前に、曖昧な指示を検証可能な具体的表現に書き直す。例えば「フォーマットを整える」ではなく「インデントは半角スペース2つにする」、「変更をテストする」ではなく「コミット前に `npm test` を実行する」のようにする。関連する指示は密な段落ではなく、見出しと箇条書きでまとめる。

### 6. 案を提示して確認を取る

変更内容を diff（新規ファイルの内容、または具体的な追記・編集箇所）として提示し、ファイルに触れる前にユーザーの承認を待つ。

### 7. 変更を反映する

承認後、実際にファイルを作成・編集する。プロジェクトに Markdown lint のタスク（例：`mise run md-fix`）があれば実行し、問題があれば完了報告の前に修正する。

## 注意事項

- 提案した diff についてユーザーの明示的な承認を得るまでは、`CLAUDE.md`、`AGENTS.md`、`.claude/rules/` に書き込まない。
- 「置けそうだから」という理由だけで `.claude/rules/` に移さない。トピックやパスで絞る意味がある場合、または正本ファイルをサイズの目安内に収めるために必要な場合のみ移す。
- `paths` frontmatter のない rules は `CLAUDE.md`／`AGENTS.md` と同様に毎セッション読み込まれる。本来どこでも必要な内容を、無理に「rule」化するためだけにスコープを狭めない。
- `CLAUDE.md` が `AGENTS.md` への薄いポインタになっている場合、プロジェクト全体の指示を `CLAUDE.md` に直接追記してはならない――正本が二重化してしまう。必ず `AGENTS.md` を編集する。
